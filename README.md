# 订阅账本

个人 Android 订阅管理工具，支持 Android 8.0（API 26）及以上。应用首次打开为空账本。

## 使用

1. 选择「添加订阅」，填写金额、币种、账期和续费日期。分类、付款渠道、实际成本、分摊人数、备注可选。
2. 选择自动续费、手动续费或已停止。自动续费按录入日期推算未来账期。手动续费在付款后点「记录已续费」，日期会顺延一个账期。
3. 免费试用：勾选「免费试用中」，续费日期填试用结束、开始扣费的日子。提醒会提示试用即将结束，首次扣费后自动取消试用标记。
4. 每项可设置提前 0–90 天提醒，0 表示当天，留空表示关闭。开启系统通知权限后，提醒按设备当地时间上午 9 点安排，Android 省电策略可能推迟送达。
5. 首页按币种显示进行中订阅的月均预算，并折合成本位币显示月度和年度合计。周付按每年 52 周折算，月付按原额，季付除以 3，年付除以 12。多人分摊的订阅只计入你承担的部分。
6. 点「统计」查看本位币下的月度、年度支出、今年和近 12 个月已支出，未来 12 个月逐月扣款（点按柱形看明细），以及按订阅、分类、付款渠道和账期的支出占比。
7. 「设置 → 余额账户」：把礼品卡或预付余额记成账户。订阅选择从账户扣款后，续费时自动扣除；余额不够下次扣款时，首页、订阅卡片和续费提醒都会提示。充值时填写实际花费，账户会按加权平均算出每单位余额的真实成本。每次充值都会留下记录，删除充值记录会从余额中减去该金额。
8. 「设置 → 扣款记录」：自动续费到期后自动记录，手动续费在「记录已续费」时记录，更早的扣款可以补记。删除从余额扣款的记录时，可选择是否退回余额。
9. 修改订阅金额或币种时会保留旧价格，详情中可查看价格变动。
10. 截图与发票：发票按账期保存。订阅详情的「每期账单与发票」列出最近几期，每期有自己的附件，点「＋ 添加」从相册或文件中选择图片或 PDF（可多选，每条记录最多 20 个，单个 25 MB 以内）。当前这一期还没有扣款记录时，可在那里直接补记后上传。不属于某一期的截图（如套餐页面）放在「订阅资料」。充值记录和扣款记录也可以各自挂附件。点按缩略图查看，长按可删除或移到其他账期，查看页里也有「删除」和「移到其他账期」。图片会压缩保存，PDF 原样保存，附件随所属记录一起删除。旧版本挂在订阅上的附件，会按添加日期自动归入当月的扣款记录；那个月没有扣款记录的留在「订阅资料」。
11. 按月导出：「设置 → 按月导出账单与发票」或扣款记录页每个月份旁的「导出」，生成一个 ZIP：一张 CSV 表格（当月每笔扣款和充值，可用 Excel 打开）加上当月全部发票，文件名形如「2026-11-12 Claude Pro USD 20.pdf」。这是给人看的账单，不能用来恢复数据。
12. 图标：常见服务（Claude、Codex、ChatGPT、Netflix、Spotify、爱奇艺、哔哩哔哩等）按名称自动显示缩写和品牌色，其余显示名称首字和固定配色。在编辑页点「更换图标」可改文字（最多 8 个字符，也可用 Emoji）和颜色，或从相册选一张图片（裁成正方形保存在本机）。应用不内置也不联网下载任何品牌 Logo。
13. 桌面小组件「订阅续费」显示每月支出和最近三项续费。
14. 界面：Material You 设计，跟随系统浅色/深色模式；Android 12 及以上按壁纸取色（应用、小组件和主题图标），可在「设置」改回应用自带的绿色。详情、编辑等面板从底部弹出，可上下拖动在半屏和全屏之间切换，下拉或点空白处关闭（有未保存的修改时会先确认）；长按订阅卡片可快速编辑、记录续费或删除。平板和桌面窗口下自动改为多列，宽屏时首页分为左右两栏。
15. 自动更新：应用每天最多检查一次 GitHub 上的最新版本，有新版本时弹出更新说明，点「下载并安装」后由系统确认安装，数据保留。「设置」里可手动检查更新，或关闭自动检查；不想装的版本可以跳过。首次更新需按提示允许本应用安装应用。
16. 可从「设置」打开 Claude 模板。模板预填币种、付款渠道及已知候选日期，保存前需自行确认金额和日期。

### 金额怎么折算

- **预计支出**（月度、年度、未来 12 个月）的每笔成本依次取：订阅填写的「每期实际成本」，从余额账户扣款的按账户实际成本，其余外币按当前汇率折算。
- **已支出**来自扣款记录。每笔的真实成本在记录时就固定为本位币金额，之后汇率变化不会改写历史。
- 统计页可选择本位币、在线获取汇率，或为单个币种手动填写汇率（手动汇率优先）。首次获取汇率后，打开应用时若汇率已超过 12 小时会自动更新。

## 数据与隐私

数据保存在设备，订阅和扣款由用户自己维护。应用只在两种情况下联网：获取汇率时向 ExchangeRate-API（open.er-api.com）请求本位币汇率；检查和下载更新时访问 GitHub（api.github.com 和 github.com 上本项目的 Release）。都不上传订阅内容。

附件保存在应用私有目录，卸载应用会一并删除。

导入和导出在「设置」中。备份为 ZIP 文件，内含明文的 `ledger.json`（订阅、余额账户、充值与扣款记录，以及你填写的付款渠道和备注）、全部附件和图标图片，请放在可信位置。汇率设置不包含在备份中。导入按记录 ID 合并，同 ID 以备份内容为准。可导入新的 ZIP 备份，也可导入以前导出的 JSON 备份（第 1–3 版）。当前备份格式为第 6 版；旧版应用无法导入新备份。

## 从源码构建

使用 Android Studio 打开此目录，安装 Android 35 SDK，选择 JDK 17 或更高版本。也可在配置好 Android SDK 和 JDK 后运行：

```bash
./gradlew :app:assembleDebug
```

Windows 上运行 `gradlew.bat :app:assembleDebug`。输出路径为 `app/build/outputs/apk/debug/app-debug.apk`。

GitHub Actions（`.github/workflows/build.yml`）在每次推送到 `main` 时先运行 lint 检查（有错误即失败），再构建正式版（release）APK 并作为 Artifact 上传；正式版不可调试，他人无法通过 USB 调试读取应用数据。推送 `v*` 标签时另外发布 Release 附带 APK，标签必须等于 `v` 加 `app/build.gradle` 里的 `versionName`，更新说明取自上一个标签以来的提交标题。应用内更新读取的就是这里的最新 Release。CI 构建使用仓库 Secrets（`SIGNING_KEYSTORE_BASE64`、`SIGNING_ALIAS`、`SIGNING_PASSWORD`）中的固定签名密钥，因此新版本可直接覆盖安装；本地构建仍使用 Android 调试密钥，与 CI 版本不能互相覆盖安装。

单独提供的体验 APK 使用测试签名。若改用自己构建的版本，先在「设置」中导出备份（ZIP，含附件），再卸载旧版、安装新版并导入备份。日后为同一安装包制作更新时，请保管并持续使用同一签名密钥。
